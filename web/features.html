Capability sheet

Everything in one window.

SalmonLauncher splits the job of a launcher into seven areas, but they share one config, one instance folder and one task queue. Here is exactly what each area does.

01 / INSTALL

Install: manifest to runnable folder

The version list comes from Mojang's official version_manifest_v2.json: the latest 40 releases plus the latest 12 snapshots and historical builds. Pick one and the launcher fills in libraries, assets and natives from the manifest, then finds or downloads a matching Java.

  • Fabric, Quilt, Forge and NeoForge loader installs
  • Automatic BMCLAPI mirror fallback when the primary source fails
  • Resume plus SHA-1 verification; mismatches are downloaded again
  • 2026 natives rules: windows-x64 only, other platforms pruned

02 / LAUNCH

Launch is a visible sequence

Launching is not a click and a wait. Every stage shows up in the task centre: parse metadata, verify libraries, rebuild natives, top up assets, locate Java, assemble arguments, start the process. Success and failure both land in the instance log.

  • Memory, window size and extra JVM arguments per instance
  • Natives are rebuilt on every launch, so stale DLLs never leak in
  • Game stdout and stderr are redirected into the instance log
  • Abnormal exits drop straight into diagnostics

03 / INSTANCES & MODS

Instances are folders, not a database

Each instance owns a full tree under instances/<id>/: meta, versions, mods, resourcepacks, shaderpacks, saves, logs, natives, crash-reports. Removing one instance touches nothing else.

  • Mod toggling is a rename: .jar ↔ .jar.disabled
  • Real metadata read from fabric.mod.json, mods.toml or mcmod.info
  • Local mods import directly, leaving the original untouched
  • Saves can be zipped for backup; migrating is a folder copy

04 / MULTIPLAYER

Multiplayer runs on Campfire

Multiplayer is handled by the bundled Campfire. Enter a world in it and the world opens to LAN with an invite code; friends join with that code. Cross-network play and the room lobby are provided by Campfire itself.

  • Invite codes: generated as soon as you enter a world, ready to send
  • Cross-network play: works beyond your LAN, with Campfire handling the connection
  • One-click updates: the launcher checks and updates Campfire, downloading over multiple mirrors verified by SHA-256
  • A separate process: Campfire runs on its own and the launcher neither takes part in nor relays any multiplayer traffic

05 / CONTENT

Content: three Modrinth categories

Mods, shaders and resource packs share one search view, while the install folder follows the category: mods, shaderpacks, resourcepacks. With an instance selected, finished downloads land in the right folder.

  • Faceted search by category and game version
  • Shaders are not pinned to a game version, so usable projects are not hidden
  • A China mirror can be selected
  • The target instance and folder are shown before install

06 / ACCOUNTS

Microsoft sign-in, three ways

Signing in does not depend on one embedded browser. Device code suits environments without a browser, and system-browser sign-in pastes the callback link back into the app. Offline accounts are unlimited, with UUIDs generated by the offline rule.

  • Embedded browser authorisation with full-page scrolling
  • Device code sign-in confirmed on any device
  • System browser sign-in opens the default browser and copies the link
  • Sessions persist locally, refresh automatically, and fall back to offline with a notice

07 / APPEARANCE

Four languages, two themes, one workshop

The interface ships in Simplified Chinese, Traditional Chinese, English and Japanese, follows the system by default and switches on demand. Light and dark can follow the system or be locked; accent colour, a block-colour theme workshop and wallpapers keep the window from being a grey slab.

  • Theme tokens swap as a whole, with no flicker
  • System-follow listens to AppsUseLightTheme in the registry
  • Custom accent applies immediately
  • Block-colour workshop and wallpapers

08 / DIAGNOSTICS

After a crash, start with the conclusion

Diagnostics read the tail of latest.log through FileStream + FileShare.ReadWrite, sidestepping log4j's file lock. Signatures cover mod conflicts, out-of-memory, Java version mismatch, missing dependencies and OpenGL, then hand back a plain-language explanation and next step.

  • No FileNotFoundException just because the log is held open
  • Signature matching instead of keyword guesswork
  • Actionable advice rather than a pasted stack trace
  • The raw log stays readable and exportable

Boundaries

What it does not do

Not in scope

  • No Minecraft game files are bundled or modified
  • No cracked servers or accounts are provided
  • Mods are not auto-updated; you choose the version
  • Multiplayer is provided by the bundled Campfire

What it relies on

  • A network connection for the first version manifest
  • Game files come from official sources or public mirrors
  • Java is downloaded on demand (Eclipse Temurin)
  • Mods and shaders remain their authors' property
